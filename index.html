        How the system works

        The platform is one stage of a loop, not the whole of it. The loop is drawn below, and each stage says whether it is built or planned.

        1. Gaps are collected

          Published research recommendations naming data that is missing about women are found, extracted and added to the platform.

          Five steps. A record passes all five before it is in the seed.

          1. Discover

            Query source APIs for research recommendations in women’s health — Europe PMC, PubMed, ClinicalTrials.gov, NICE research recommendations, Cochrane “implications for research”.

          2. Filter

            A cheap model answers one yes/no question: is this a research recommendation about women’s health?

          3. Extract

            Structured output strictly against the data.js schema. Anything the source text does not support comes back null, not a guess.

          4. Validate

            Ordinary JavaScript, no model: schema, status against the presence of gap_evidence, duplicates by DOI.

          5. Review

            A pull request with a diff of data.js. A human merges.

          Most tools point a model at a problem and let it generate the answer. This one inverts that. Where the data gap is, is a claim, and every claim here comes from a published research recommendation. AI is used for finding, extracting and matching — never for making the claim. What the platform adds on top of the borrowed claim is labelled as its own on every screen.

        2. The platform shows what is missing

          For each problem: which data is needed, what status it has, and a collection request saying which women, which variables, which breakdowns, in what form.

        3. A researcher picks up a request

          And designs a study from it. The platform ends exactly where study design begins.

        4. Women on the platform join the study

          Women who want the gap in their own problem closed take part in it.

        5. The collected data closes the gap

          And the record’s status changes. The loop returns to stage 2.

        Who built it, and how

        • Built by Marina, solo, for the Elevate Women Global Hackathon 2026.
        • Plain HTML, CSS and JavaScript. No framework, no build step, no dependencies — three screens and one seed file do not need one, and a build is one more thing that can fail on submission day. It opens by double-clicking index.html.
        • Two-tier provenance. The gap claim is borrowed and cited; the collection request — which women, which variables, which breakdowns, in what form — is this platform’s own specification in every record.
        • Disclosure. Everything in this repository was written during the Hackathon Period, 14–20 September 2026. No pre-existing code was used; an earlier personal project by the same author shares no code with this one. Development was AI-assisted throughout, using Claude Code; the git history is the record.
